# Модель данных

## Общая структура модели

В модели выделены следующие сущности:

* **Клиент**
* **Тренер**
* **Занятие**
* **Абонемент**
* **Запись на занятие**
* **Посещение**
* **Тренажёр**


## Сущности и атрибуты

### Клиент

Хранит информацию о зарегистрированных клиентах фитнес-клуба.

| Атрибут             | Тип данных   | Описание                         | Ограничения          |
| ------------------- | ------------ | -------------------------------- | -------------------- |
| `client_id`         | INTEGER      | Уникальный идентификатор клиента | PK                   |
| `name`              | VARCHAR(100) | Имя клиента                      | NOT NULL             |
| `phone`             | VARCHAR(20)  | Номер телефона                   | UNIQUE               |
| `email`             | VARCHAR(100) | Электронная почта                | UNIQUE               |
| `birth_date`        | DATE         | Дата рождения клиента            | NOT NULL             |
| `registration_date` | DATE         | Дата регистрации в клубе         | DEFAULT CURRENT_DATE |


---

### Тренер

Хранит информацию о тренерах фитнес-клуба.

| Атрибут            | Тип данных   | Описание                         | Ограничения |
| ------------------ | ------------ | -------------------------------- | ----------- |
| `trainer_id`       | INTEGER      | Уникальный идентификатор тренера | PK          |
| `name`             | VARCHAR(100) | Имя тренера                      | NOT NULL    |
| `specialization`   | VARCHAR(50)  | Специализация тренера            | NOT NULL    |
| `experience_years` | INTEGER      | Стаж работы в годах              | CHECK ≥ 0   |


---

### Занятие

Описывает запланированное или проведённое занятие, которое проводит тренер.

| Атрибут            | Тип данных  | Описание                                     | Ограничения                         |
| ------------------ | ----------- | -------------------------------------------- | ----------------------------------- |
| `session_id`       | INTEGER     | Уникальный идентификатор занятия             | PK                                  |
| `trainer_id`       | INTEGER     | Идентификатор тренера                        | FK → `trainer.trainer_id`, NOT NULL |
| `type`             | VARCHAR(50) | Тип занятия                                  | NOT NULL                            |
| `start_time`       | TIMESTAMP   | Дата и время начала занятия                  | NOT NULL                            |
| `duration_minutes` | INTEGER     | Продолжительность занятия в минутах          | CHECK 30–180                        |
| `max_participants` | INTEGER     | Максимально допустимое количество участников | CHECK 1–50                          |


---

### Абонемент

Хранит информацию об абонементе клиента и периоде его действия.

| Атрибут            | Тип данных  | Описание                            | Ограничения                       |
| ------------------ | ----------- | ----------------------------------- | --------------------------------- |
| `membership_id`    | INTEGER     | Уникальный идентификатор абонемента | PK                                |
| `client_id`        | INTEGER     | Идентификатор владельца абонемента  | FK → `client.client_id`, NOT NULL |
| `type`             | VARCHAR(20) | Тип абонемента                      | NOT NULL                          |
| `start_date`       | DATE        | Дата начала действия                | NOT NULL                          |
| `end_date`         | DATE        | Дата окончания действия             | NOT NULL                          |
| `status`           | VARCHAR(20) | Текущий статус абонемента           | NOT NULL                          |
| `visits_remaining` | INTEGER     | Количество оставшихся посещений     | CHECK ≥ 0                         |

Допустимые типы абонементов:

* `разовый`
* `месячный`
* `годовой`

Допустимые статусы:

* `активен`
* `закончен`
* `заблокирован`

Один клиент может иметь несколько абонементов за весь период обслуживания. 

Для разового абонемента используется атрибут `visits_remaining`. При создании разового абонемента ему устанавливается значение `1`. После фактического посещения занятия значение уменьшается до `0`, а абонемент переводится в статус `закончен`.

Для месячного и годового абонемента значение `visits_remaining` не используется и может быть `NULL`.

---

### Запись на занятие

Связывает клиента с выбранным занятием и хранит информацию о бронировании места.

| Атрибут        | Тип данных  | Описание                        | Ограничения                         |
| -------------- | ----------- | ------------------------------- | ----------------------------------- |
| `booking_id`   | INTEGER     | Уникальный идентификатор записи | PK                                  |
| `client_id`    | INTEGER     | Идентификатор клиента           | FK → `client.client_id`, NOT NULL   |
| `session_id`   | INTEGER     | Идентификатор занятия           | FK → `session.session_id`, NOT NULL |
| `booking_date` | TIMESTAMP   | Дата и время создания записи    | DEFAULT CURRENT_TIMESTAMP           |
| `status`       | VARCHAR(20) | Статус записи                   | NOT NULL                            |

Допустимые статусы записи:

* `подтверждена`
* `отменена`

Для одного клиента и одного занятия может существовать не более одной записи.

---

### Посещение

Хранит информацию о фактическом результате посещения клиентом занятия.

| Атрибут             | Тип данных  | Описание                           | Ограничения                                 |
| ------------------- | ----------- | ---------------------------------- | ------------------------------------------- |
| `attendance_id`     | INTEGER     | Уникальный идентификатор посещения | PK                                          |
| `booking_id`        | INTEGER     | Идентификатор записи на занятие    | FK → `booking.booking_id`, UNIQUE, NOT NULL |
| `attendance_status` | VARCHAR(20) | Результат посещения                | NOT NULL                                    |
| `attendance_time`   | TIMESTAMP   | Дата и время фиксации результата   | —                                           |

Допустимые значения `attendance_status`:

* `посетил`
* `неявка`

Для одной записи может быть зафиксировано не более одного результата посещения.

---

### Тренажёр

Хранит информацию об оборудовании фитнес-клуба и его текущем состоянии.

| Атрибут            | Тип данных   | Описание                           | Ограничения          |
| ------------------ | ------------ | ---------------------------------- | -------------------- |
| `equipment_id`     | INTEGER      | Уникальный идентификатор тренажёра | PK                   |
| `name`             | VARCHAR(100) | Название тренажёра                 | NOT NULL             |
| `type`             | VARCHAR(20)  | Тип оборудования                   | NOT NULL             |
| `status`           | VARCHAR(20)  | Текущее состояние оборудования     | NOT NULL             |
| `last_maintenance` | DATE         | Дата последнего обслуживания       | DEFAULT CURRENT_DATE |

Допустимые типы оборудования:

* `кардио`
* `силовое`

Допустимые статусы:

* `доступен`
* `занят`
* `обслуживание`

---

# Связи между сущностями

## Клиент — Абонемент

**Связь: 1:N**

Один клиент может иметь несколько абонементов за весь период обслуживания.

Каждый абонемент принадлежит одному клиенту.


## Клиент — Запись на занятие

**Связь: 1:N**

Один клиент может иметь множество записей на различные занятия.

Каждая запись относится к одному клиенту.


## Тренер — Занятие

**Связь: 1:N**

Один тренер может проводить множество занятий.

Каждое занятие проводится одним тренером.

---

## Занятие — Запись на занятие

**Связь: 1:N**

Одно занятие может иметь множество записей клиентов.

Каждая запись относится к одному занятию.

---

## Запись — Посещение

**Связь: 1:0..1**

Одна запись может не иметь результата посещения, если занятие ещё не состоялось.

После проведения занятия для записи может быть создана одна запись о посещении.
