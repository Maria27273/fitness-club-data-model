# Проверка бизнес-правил

Проверим, что БД действительно не позволяет нарушать бизнес-правила.

### 1. Один активный абонемент на клиента

Попробуем создать второй активный абонемент для клиента, у которого уже есть активный абонемент.

Операция должна завершиться ошибкой.

```sql
INSERT INTO membership
(client_id, type, start_date, end_date, status, visits_remaining)
VALUES
(1, 'месячный', '2026-09-05', '2026-10-05', 'активен', NULL);
```

---

### 2. Дата окончания не может быть раньше даты начала

Создадим абонемент с некорректным периодом.

Операция должна завершиться ошибкой.

```sql
INSERT INTO membership
(client_id, type, start_date, end_date, status, visits_remaining)
VALUES
(1, 'месячный', '2026-10-01', '2026-09-01', 'активен', NULL);
```

---

### 3. Просроченный абонемент должен завершаться

Проверим наличие активных абонементов, срок действия которых уже закончился.

```sql
SELECT
    membership_id,
    client_id,
    end_date,
    status
FROM membership
WHERE status = 'активен'
  AND end_date < CURRENT_DATE;
```

Запустим функцию, которая переводит просроченные абонементы в статус `закончен`.

```sql
SELECT update_expired_memberships();
```

Повторно проверим результат.

```sql
SELECT
    membership_id,
    client_id,
    end_date,
    status
FROM membership
WHERE end_date < CURRENT_DATE;
```

У просроченных абонементов статус должен измениться на `закончен`.

---

### 4. Разовый абонемент заканчивается после посещения

Проверим, что после фактического посещения разового абонемента количество оставшихся посещений становится равным `0`, а абонемент переходит в статус `закончен`.

Сначала посмотрим текущие данные.

```sql
SELECT
    membership_id,
    client_id,
    type,
    visits_remaining,
    status
FROM membership
WHERE type = 'разовый';
```

Зарегистрируем посещение клиента.

```sql
INSERT INTO attendance
(booking_id, attendance_status, attendance_time)
VALUES
(3, 'посетил', CURRENT_TIMESTAMP);
```

Проверим состояние абонемента после посещения.

```sql
SELECT
    membership_id,
    client_id,
    type,
    visits_remaining,
    status
FROM membership
WHERE client_id = 3
  AND type = 'разовый';
```

После посещения должно быть:

```text
visits_remaining = 0
status = закончен
```

### 5. Запись на занятие только при наличии действующего абонемента

Попробуем записать клиента, у которого нет действующего абонемента.

Операция должна завершиться ошибкой.

```sql
INSERT INTO booking
(client_id, session_id, status)
VALUES
(4, 1, 'подтверждена');
```

---

### 6. Нельзя превысить максимальное количество участников

Попробуем записать клиента на занятие после того, как количество подтверждённых записей достигло максимальной вместимости.

Операция должна завершиться ошибкой.

```sql
INSERT INTO booking
(client_id, session_id, status)
VALUES
(8, 1, 'подтверждена');
```

---

### 7. Нельзя создать две активные записи на одно занятие

Попробуем повторно записать клиента на то же занятие.

Операция должна завершиться ошибкой.

```sql
INSERT INTO booking
(client_id, session_id, status)
VALUES
(1, 1, 'подтверждена');
```

При этом отменённая запись не должна препятствовать новой записи клиента на это же занятие.

---

### 8. Клиент не может быть записан на пересекающиеся занятия

Попробуем записать клиента на занятие, время которого пересекается с другим подтверждённым занятием этого клиента.

Операция должна завершиться ошибкой.

```sql
INSERT INTO booking
(client_id, session_id, status)
VALUES
(1, 2, 'подтверждена');
```

---

### 9. Тренер не может проводить два занятия одновременно

Попробуем создать для тренера занятие, время которого пересекается с уже запланированным занятием этого тренера.

Операция должна завершиться ошибкой.

```sql
INSERT INTO session
(trainer_id, type, start_time, duration_minutes, max_participants)
VALUES
(1, 'Силовая тренировка', '2026-09-10 10:30:00', 60, 10);
```

---

Попробуем создать подтверждённую запись для клиента, которому 14 лет или меньше.

Операция должна завершиться ошибкой.

```sql
INSERT INTO booking
(client_id, session_id, status)

(7, 1, 'подтверждена');
```

---

### 11. Нельзя удалить клиента с будущими подтверждёнными записями

Попробуем удалить клиента, у которого есть будущая запись на занятие.

Операция должна завершиться ошибкой.

```sql
DELETE FROM client
WHERE client_id = 1;
```

---

### 12. Нельзя удалить тренера с запланированными занятиями

Попробуем удалить тренера, у которого есть будущие занятия.

Операция должна завершиться ошибкой.

```sql
DELETE FROM trainer
WHERE trainer_id = 1;
```

---

### 13. Нельзя удалить занятие с подтверждёнными записями

Попробуем удалить занятие, на которое уже записаны клиенты.

Операция должна завершиться ошибкой.

```sql
DELETE FROM session
WHERE session_id = 1;
```
